# 《程序设计基础课程设计》题签

**小组成员**：郭承宇（组长）/ 李阳旭

---

## 正文

编写一个C++17程序，面向中小型医院/社区卫生服务中心，实现轻量级医院信息管理系统（HIS），动态管理患者档案、医疗记录、病房床位、药品库存及其基本操作。系统核心功能如下：

### 1. 用户的注册，登录控制

a) 用户分为**普通患者、医生、护士、药房药剂师、系统管理员**五类，权限划分如下：

- 患者：预约挂号、查看自身病历/检查报告/住院信息、查询处方明细、缴纳挂号费/检查费/处方药费/住院费、查看与修改个人信息（修改密码、查看ID、充值余额）；
- 医生：查看挂号信息并依据挂号接诊、登记主诉/病史/诊断、开具检查单与处方、发起住院审批、管理个人看诊与检查记录；
- 护士：查看病房信息并根据医生开具的住院证安排病房、管理住院记录（创建/出院/转科）、录入体征数据、管理床位信息；
- 药剂师：处方审核、药品出入库管理、发药与退药确认、药品库存维护与流水记录查看；
- 管理员：基础操作+基础字典维护、账号解封/封禁、全局数据查询与管理（含医生/护士/药剂师/患者五类人员、挂号/看诊/检查/住院/用药五类医疗记录、药品/床位管理）、统计报表与数据分析预测、排班管理、操作日志审计。

b) 安全规范：本地数据文件不存储明文密码。采用 SHA-256 加盐（Salt）哈希算法，结合 1000 次迭代（Key Stretching）技术进行加密存储，有效防止彩虹表攻击和暴力破解。哈希验证采用基于 volatile XOR 的逐字节比较，防止时序攻击侧信道泄露。

c) 防暴力破解：用户连续 5 次输入错误密码，账户自动锁死，锁定密码输入通道，仅管理员可解封。登录成功后自动重置失败计数。

### 2. 核心信息管理（用户档案、医疗记录、病房床位、药品库存）

a) 数据结构：十三类核心业务数据均采用**动态内存双向链表**实现，支持增、删、查、改全功能：

- **五类用户信息**：管理员、医生、护士、药剂师、患者各维护一条独立链表。用户基础信息包含 ID（6位，首位标识角色）、姓名、密文密码、加密盐、性别、年龄、电话、邮箱、科室（医护人员）、职称（医生）、创建时间、账号状态等字段；
- **五类医疗记录**：挂号（Registration）、看诊（Consultation，含处方子结构与检查项目列表）、检查（Examination，含生命体征 VitalSigns）、住院（Hospitalization）、用药记录（MedicationRecord，含药品行明细 MedicationLine），记录需包含时间戳、主诉、初步诊断、医嘱、检查项目/报告状态、床位分配等字段，强关联患者与医护人员 ID；
- **药品与流水**：药品（Medicine）包含通用名、别名、规格、进价、售价、库存、安全阈值、有效期、关联科室，支持出入库流水（MedicineFlow）记录，跟踪入库/出库/处方扣减/退药归还等操作类型、数量、操作人与原因；
- **住院病房与床位**：床位（bedInfo）包含病房类型（普通/隔离/VIP/ICU）、关联科室、床位状态（空闲/占用）、收费标准、当前绑定患者 ID 与护士 ID，支持状态机流转与跨科室转科协调。

b) 查询功能：支持按科室、状态、患者 ID、医生 ID 等多维度筛选，单个患者/药品/科室**一键下钻查询**历史就诊、处方、检查报告、床位流转记录。管理员支持全院/分科室两种视图。

c) 时间规范：录入自动生成**系统时间戳**（MyTime 单例，格式 `YYYY-MM-DD hh:mm:ss`），程序内部维护严格时间顺序，保障病历追溯与财务对账。

d) 【数据字典与关联约束】：

- 科室与医生：预设 5 个标准科室（内科、外科、儿科、妇产科、急诊科），每科室绑定多名医生，支持医生排班管理与跨科会诊归档；
- 病房类型与科室：4 种病房（普通 50 元/天、隔离 100 元/天、VIP 200 元/天、ICU 500 元/天），按科室分配床位，支持跨科转科与日志记录；
- 药品分类与科室：支持按科室关联药品（专科药标记），动态存储与模糊检索；
- 容量与重名：容纳 ≥100 名门诊患者、≥30 名住院患者，以**6位业务 ID**（首位角色标识+5位序号）为唯一主键，动态内存支持超长文本存储，无数据截断；
- 费用标准：挂号费按医生职称分级（实习 10 / 住院医师 20 / 主治 30 / 副高 40 / 正高 50 元），检查费按项目名称定价（2-30 元，14 项），住院费按病房类型×天数计算。

### 3. 数据文件管理

a) 核心链表（五类用户信息、五类医疗记录、药品信息、药品流水、床位信息）各对应一份 txt 数据文件，采用 CSV 逗号分隔格式存储，空值字段使用 `"#"` 哨兵值标记；

b) 数据文件按 `UserData/` 与 `RecordData/` 子目录分类存放，目录结构清晰（如 `Data/UserData/AdminChainData/admin_users.txt`、`Data/RecordData/MedicineChainData/medicines.txt`）；

c) 程序注册 SIGINT/SIGABRT/SIGTERM 信号处理函数，在意外退出（Ctrl+C、崩溃等）时自动执行紧急数据保存，将内存中全部链表写回文件，实现数据零丢失。

### 4. 医院运营情况查询

支持分级统计查询，所有结果均以**控制台 Unicode 双线框格式化报表**形式呈现（`╔═╗║╚═╝`），覆盖三类视角：

- 管理视角：科室统计报表（入院/出院人数、挂号总数、住院费用、床位日数）、医生工作量报表、患者人口统计、床位利用率报表、药品库存报表、全院概览报表，以及**数据分析与预测**模块（基于3个月移动平均+线性回归+增长率的需求预测、床位分配优化建议、药品利润率分析）；
- 医护视角：个人工作量统计、待办清单、本人名下的挂号/看诊/检查/住院记录管理；
- 患者视角：个人费用明细、就诊时间轴（挂号→看诊→检查→住院全链路可追溯）。

### 5. 非法输入检测

所有输入环节添加**类型、范围、长度、格式校验**，拦截越界值、非法字符、空值提交，防止程序崩溃与内存泄漏。具体包括：

- 范围选择校验（`selectIntCheck`）：限定菜单选项的合法范围；
- 费用输入校验（`feeCheck`）：验证金额格式与合理范围；
- 字符串输入校验（`inputStringCheck`）：禁止英文逗号（防止 CSV 分隔符冲突）、过滤非法字符；
- ID 格式校验（`idCheck`）：验证 6 位数字 ID 格式；
- 密码输入校验（`inputHiddenPwdCheck`）：隐藏密码输入，使用 Windows ReadFile API 绕过回显。

### 6. 特色功能

a) **SHA-256 加盐哈希加密**：采用业界标准 SHA-256 算法，每个用户生成独立 16 字符随机盐值，密码经 1000 次迭代哈希后存储（格式：`salt$hash`），有效抵御彩虹表攻击与暴力破解。哈希比对采用 volatile XOR 逐字节异或方式，实现时序安全比较，防止侧信道攻击；

b) **数据分析与预测**：通过梯度下降+线性回归算法，对历史床位使用数据进行拟合，预测未来床位需求与营收趋势，控制台输出拟合参数与预测数值。结合 3 个月移动平均法进行需求预测，支持床位调配建议（调入/调出科室及数量）、药品利润率分析；

c) **信号中断紧急保存**：注册 SIGINT、SIGABRT、SIGTERM 信号处理函数，在程序意外退出时自动遍历全部 13 条链表并执行数据保存，确保任何时刻内存数据与文件数据一致，实现数据零丢失；

d) **操作日志审计**：`LogManager` 单例类实现线程安全的结构化操作日志，所有登录/注册/数据修改操作自动记录（操作人 ID、角色、操作类型、详情、时间戳），按日期自动分割至 `Data/OperationLog/his_YYYY_MM_DD.log`；

e) **控制台交互增强**：Unicode 双线框菜单系统（自动 CJK 宽度对齐）、彩色输出（成功/错误/警告分色）、分页显示（支持上一页/下一页/跳转）、面包屑导航路径（如"管理员 > 医疗记录 > 挂号管理"）、隐藏密码输入；

f) **泛型账户管理**：`Login.h` 使用 C++ 模板编程实现 `AccountManageGeneric<UserType>` 泛型函数，统一实现五类角色的账户激活/封锁操作，消除代码重复；

g) **标准化开发**：采用 MSVC + CMake 跨平台编译工具，模块化拆分 `Head/`（头文件）与 `Source/`（实现）目录，header-only 第三方库（cpp-httplib、nlohmann/json）直接置于 `Head/`，零外部构建依赖。

### 7. 小组工作流

a) 版本控制：使用 Git 管理代码，托管至 Gitee，答辩前设为公开权限；
b) 代码规范：头文件 PascalCase（如 `Doctor.h`）、函数 camelCase（如 `addDoctor()`）、匹配的源文件对应头文件，禁止魔法数字（硬编码数字提取为常量），复杂函数添加注释；
c) 分支管理：保护 main/master 分支，组长负责合并与 Code Review，成员独立分支开发；
d) 文档维护：编写 README.md，包含更新日志、Todo-List（Done-已实现 / Todo-计划 / Optimize-可优化）、架构说明、BUG 记录。
