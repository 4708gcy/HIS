### 1. 五角色权限体系与账户安全

系统设置管理员、医生、护士、药剂师、患者五类用户。五类用户均继承自 `User` 基类，在各自链表中保存账户和业务字段。用户 ID 为 6 位数字，首位表示角色（0-管理员、1-医生、2-护士、3-药剂师、4-患者），后五位由该角色计数器递增生成。

注册和修改密码时，系统生成 16 位随机盐值，使用 SHA-256 算法进行 1000 次迭代哈希，保存格式为 `salt$hash`。密码验证时采用恒时比较（volatile XOR 循环），防止时序攻击。登录校验失败达到 5 次后，账户会被锁定（`isAccountActive = false`），需由管理员重新激活。

### 2. 双向链表与文本文件持久化

系统主要数据均采用动态内存双向链表保存，节点中包含 `prev` 与 `next` 指针。链表包括 5 类用户链表，以及挂号、看诊、检查、住院、用药、药品、床位等业务链表。新增节点使用头插法（O(1)）加入链表，删除操作采用设置 `isDeleted` 标志的逻辑删除方式，避免物理删除带来的指针断裂风险。

`std::vector<T>` 提供动态扩容、随机访问和遍历操作，用于结构体内部的嵌套集合（如处方列表、检查项目列表、药品别名、用药明细、附件列表等）。

程序启动时从 txt 文件加载数据到链表，退出或异常保存时再写回对应文件。空字段统一使用 `"#"` 作为占位符。结构体中的嵌套链表（如看诊记录中的处方列表、附件列表）以附加行形式写入，行首带有 `PRESCRIPTION:`、`ATTACHMENT:`、`EXAMINATION_ITEM:`、`VITAL_SIGNS:`、`MEDICATION_LINE:`、`ALIAS:` 等标记前缀。

### 3. 终端菜单与输入校验

终端界面由 `UI.cpp` 中的公共函数统一绘制，使用 Unicode 双线框（`╔═╗║╚═╝`）显示菜单，配合彩色提示（`printSuccess` 绿色、`printError` 红色、`printWarning` 黄色）、CJK 字符宽度计算（`getDisplayWidth()`，中文计为 2 列）、信息卡片（`printInfoCard()`，固定 50 列宽）和隐藏密码输入（`inputHiddenPwdCheck()`，Windows API `ReadFile` 逐字符读取，回显 `*`）等功能，使终端交互更加清晰。

输入方面，系统提供 20 余种校验函数：菜单选项范围（`selectIntCheck`）、金额（`inputFeeCheck`）、整数（`inputIntCheck`）、浮点数（`inputDoubleCheck`）、字符串（`inputStringCheck`，拒绝中英文逗号）、用户 ID（`inputIDCheck`，6 位数字首位 0-4）、记录 ID（`inputRecordIDCheck`，前缀+6 位数字）、密码（`inputPwdCheck`/`inputHiddenPwdCheck`，8 位以上含字母和数字）、性别、电话、邮箱、年龄、日期、科室、身份证号、床位编号等多类校验函数，减少非法输入对程序运行和文本文件结构造成影响。

### 4. 医疗业务流程串联

系统将挂号、看诊、检查、用药和住院记录通过 ID 字段串联，形成完整的医疗业务闭环：

| 流程步骤 | 创建角色  | 记录类型         | ID 前缀 | 关联字段                                                |
| -------- | --------- | ---------------- | ------- | ------------------------------------------------------- |
| 预约挂号 | 患者      | Registration     | `reg` | patientID, doctorID                                     |
| 看诊记录 | 医生      | Consultation     | `con` | registrationID, patientID, doctorID                     |
| 检查记录 | 医生/护士 | Examination      | `exa` | consultationID, patientID, doctorID                     |
| 用药记录 | 药剂师    | MedicationRecord | `mrd` | consultationID, doctorID, patientID                     |
| 住院记录 | 护士      | Hospitalization  | `hos` | consultationID, patientID, doctorID, nurseID, bedNumber |

患者可预约挂号并缴纳挂号费（按医生职称计费）；医生可根据已缴费挂号创建看诊记录，填写病情信息、检查项目、处方和住院建议；医生或护士可维护检查记录；药剂师可根据处方创建用药记录、审核处方并在患者缴费后发药（发药时自动扣减库存）；护士可根据住院建议创建住院记录，完成床位分配、床位调整、押金设置和出院办理（住院费用按病房类型×天数计费）。

### 5. 药品、床位与费用管理

系统根据医生职称计算挂号费，根据检查项目计算检查费（2-30 元/项，共 14 种检查项目），根据病房类型和住院天数计算住院费用。药品模块保存药品名称、规格、厂家、进价、售价、库存、安全库存、有效期、通用名、别名和状态等信息；药品状态分为正常、低库存、已过期、已停用四类。

床位模块保存病房类型（普通/隔离/VIP/ICU）、科室、区域号、病房号、床位号、状态（占用/清洁中/可分配/不可用）、绑定患者、绑定护士、使用次数和占用天数等信息。床位编号由科室代码 + 区域号 + 病房类型代码 + 病房号 + 床位号自动组合生成（如 `N-03-P-001-01` 表示内科 3 区普通病房 1 号房 1 号床）。

### 1. 启动、注册与登录

程序启动后首先设置控制台编码为 UTF-8（`SetConsoleOutputCP(CP_UTF8)`），然后依次调用各 `loadXxxData()` 函数加载所有数据文件到内存双向链表。若管理员链表为空，系统提示必须先注册管理员账户（管理员注册需验证 API Key："88888888"）。随后进入登录/注册主菜单，用户可选择登录、注册或退出系统。

注册时，系统根据用户选择的角色生成不同前缀的 6 位用户 ID，并采集姓名、性别、年龄、电话、邮箱、科室、职称或等级等必要信息。密码经过加盐哈希后保存。登录时，系统根据角色和 ID 在对应链表中查找账户，校验密码（SHA-256 恒时比较）、逻辑删除标志和账户锁定状态。登录成功后进入相应角色主菜单，退出角色菜单后回到登录/注册主菜单。

管理员主菜单包含账户管理、医疗记录管理、药品管理、床位管理、管理员信息管理、个人信息管理、账号封锁管理和统计报表八类功能。

**账户管理**可按"全院"或指定科室管理医生、护士、药剂师、患者和管理员信息。管理员可查看列表、按 ID 查询、按姓名或状态筛选，也可以添加新账户、修改账户字段和逻辑删除账户。不同角色的可修改字段与其结构体字段一致，例如医生包含科室、职称、擅长方向、排班信息和工作量计数，患者包含身份证号、地址、紧急联系人、过敏史、既往病史、账户余额和就医次数等。底层通过 `Login.h` 中的模板函数 `AccountManageGeneric<UserType>()` 统一处理各角色链表的增删改查。

**医疗记录管理**包括挂号记录、看诊记录、检查记录、住院记录和用药记录。管理员可查看、添加、修改状态或内容、删除记录，并可按科室、状态、患者 ID、医生 ID、护士 ID、药剂师 ID 或记录 ID 等条件筛选。记录删除均通过 `isDeleted` 标志实现，不会物理删除数据。

**药品管理**包括药品信息维护（名称、规格、进价、售价、库存、安全库存、生产日期、有效期、厂家、通用名、别名、状态）和库存增减操作。

**床位管理**用于维护床位链表（状态、病房类型、科室、区域号、病房号、床位号、备注、绑定患者、绑定护士、使用次数、占用天数），床位编号由科室代码 + 区域号 + 病房类型代码 + 病房号 + 床位号自动组合生成。

**账号封锁管理**使用 `Login.h` 中的模板函数 `AccountManageGeneric<UserType>()` 统一处理五类角色账户状态。管理员可查看账户是否可用，并对账户执行激活（重置 `loginAttempts`）或封锁操作。

**统计报表**包含科室统计总览、医生工作量统计、患者就诊统计、床位使用率统计和药品库存统计，直接基于当前链表遍历汇总。

### 7. 数据文件与运行维护

系统数据文件分为用户数据和业务记录数据两大类。用户数据包括管理员、医生、护士、药剂师、患者；业务记录包括挂号、看诊、检查、住院、床位、用药记录和药品信息。文本字段为空时统一保存为 `"#"` 占位符。

嵌套数据（如看诊记录中的处方、附件、检查项目列表、药品别名、关联记录 ID 列表等）采用附加行保存，行首带有标记前缀：`PRESCRIPTION:`、`ATTACHMENT:`、`EXAMINATION_ITEM:`、`ALIAS:`、`RELATED_REGISTRATION_ID:`、`RELATED_CONSULTATION_ID:`、`RELATED_EXAMINATION_ID:`、`RELATED_HOSPITALIZATION_ID:`、`MEDICATION_LINE:` 等。`VITAL_SIGNS:` 行采用分号分隔的键值对格式存储 15 项生命体征数据。每条记录的最后一行固定为 `count:N`，保存该类型记录的当前 ID 计数器值。

程序正常退出时会依次保存各条链表并释放动态分配的链表节点。异常退出（Ctrl+C、信号触发）时通过 `emergencySave()` 尽可能保证数据不丢失。紧急保存函数通过双重指针获取最新链表头，确保头插法新增的节点不会丢失。

## V. 总结

本次课程设计完成了一个以 C++17 编写的控制台医院信息管理系统。程序使用面向对象思想组织五类用户，通过双向链表维护动态数据，通过 txt 文件完成持久化保存，并围绕挂号 → 看诊 → 检查 → 用药 → 住院 → 药品 → 床位 → 账户管理构建了较完整的业务流程。

**主要技术特点总结：**

| 技术点         | 实现方式                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------- |
| 编程语言与标准 | C++17，仅依赖 C++ 标准库，无第三方外部依赖                                                  |
| 数据结构       | 12 条双向链表（5 类用户 + 7 类业务记录），`std::vector<T>` 管理嵌套集合                   |
| 密码安全       | SHA-256 + 16 位随机盐值 + 1000 次迭代 + volatile 恒时比较，连续 5 次失败锁定账户            |
| ID 体系        | 6 位数字 ID，首位区分角色，后 5 位递增；业务记录 ID 带有类型前缀（reg/con/exa/mrd/hos/med） |
| 数据持久化     | 自定义 CSV 格式 + 嵌套数据附加行标记，逻辑删除（isDeleted）策略                             |
| 输入校验       | 20 余种校验函数，覆盖 ID、密码、金额、日期、科室、电话、邮箱、身份证号、床位编号等          |
| 异常保护       | SIGINT/SIGABRT/SIGTERM 信号处理 + try-catch 异常捕获 + emergencySave 双重指针紧急保存       |
| 终端 UI        | Unicode 双线框菜单 + CJK 宽度计算 + 彩色输出 + 信息卡片 + 隐藏密码输入                      |
| 操作审计       | LogManager 单例（互斥锁线程安全），按日期写入结构化操作日志                                 |
| 版本管理       | Git + CMake + DevelopLog.md 开发日志                                                        |
